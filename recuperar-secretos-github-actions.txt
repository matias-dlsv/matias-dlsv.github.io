RECUPERAR UN SECRETO DE GITHUB ACTIONS QUE NO SE PUEDE VER
==========================================================

Contexto: GitHub nunca vuelve a mostrar el valor de un secreto una vez guardado
(solo permite reemplazarlo o borrarlo). Pero el enmascarado de los logs busca el
texto EXACTO del secreto: si lo transformas antes de imprimirlo (por ejemplo en
base64), el log no lo censura. Sirve solo para secretos de TU repo.

AVISO: no pegues el valor recuperado en chats, issues ni documentos. Dejalo
directo en una variable de entorno local.


PASO 0: workflow temporal (en una rama aparte, NUNCA en la rama que despliega)
------------------------------------------------------------------------------
Crea .github/workflows/debug-secret-temporal.yml:

    name: debug-secret-temporal
    on:
      workflow_dispatch:
    jobs:
      print:
        runs-on: ubuntu-latest
        steps:
          - name: Imprimir secreto en base64
            run: |
              echo "MI_SECRETO (base64):"
              echo "${{ secrets.MI_SECRETO }}" | base64

Subelo en una rama nueva, creada desde la rama correcta:

    git checkout -b recuperar-secreto
    git add .github/workflows/debug-secret-temporal.yml
    git commit -m "temp: recuperar secreto"
    git push origin recuperar-secreto

CUIDADO: NO lo mezcles a main "para que aparezca en Actions". Un merge arrastra
todo lo que la rama tenga de mas y, si main despliega con cada push, dispara un
deploy real con codigo no validado.


PASO 1: token personal (2 minutos)
----------------------------------
github.com > Settings > Developer settings > Personal access tokens >
Tokens (classic) > Generate new token
  - Scope: solo "repo" (si el repo es privado)
  - Expiracion: la mas corta posible (7 dias)
  - Copialo: no se vuelve a mostrar


PASO 2: disparar el workflow por API contra la rama (sin tocar main)
--------------------------------------------------------------------
PowerShell:

    $token = "PEGA_TU_TOKEN_AQUI"
    curl -X POST `
      -H "Authorization: Bearer $token" `
      -H "Accept: application/vnd.github+json" `
      https://api.github.com/repos/TU_ORG/TU_REPO/actions/workflows/debug-secret-temporal.yml/dispatches `
      -d '{\"ref\":\"recuperar-secreto\"}'

Respuesta vacia con codigo 204 = funciono. Un 404 significa que ni por API
encuentra el workflow: revisa que el archivo exista en esa rama.


PASO 3: leer el log
-------------------
Pestana Actions del repo > abre el run > job "print" > copia la linea en base64.


PASO 4: decodificar en tu maquina
---------------------------------
PowerShell:

    [System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String("PEGA_BASE64"))

Git Bash / WSL:

    echo "PEGA_BASE64" | base64 -d

Dejalo directo en el lugar donde se usa, por ejemplo:

    $env:MI_SECRETO = "<valor decodificado>"


PASO 5: limpieza (obligatoria)
------------------------------
    git push origin --delete recuperar-secreto

  - Borra el run en Actions (los tres puntos del run > Delete workflow run),
    para que el base64 no quede en los logs.
  - Revoca el token personal en github.com > Settings > Developer settings.
  - Borra la rama local: git branch -D recuperar-secreto
